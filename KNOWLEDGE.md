# KNOWLEDGE.md — правила значимых изменений

Этот файл — **источник истины** для определения того, какое изменение между
прогонами price tracker считается значимым.

Правила описаны здесь и **только здесь**. В `.claude/skills/tracker/SKILL.md` они
не дублируются: позже `tracker` должен читать `KNOWLEDGE.md` и применять правила
из него. При расхождении между этим файлом и любым другим описанием правил
действует `KNOWLEDGE.md`.

Сравнение всегда идёт по одному и тому же URL: запись текущего прогона
сопоставляется с записью предыдущего прогона.

## 1. Изменение `regular_price`

Порядок проверки:

1. Предыдущее значение `null`, текущее — число: **значимое изменение**.
2. Предыдущее значение число, текущее — `null`: **значимое изменение**.
3. Предыдущее значение равно `0`: процентную формулу не применять. Переход
   `0 -> ненулевое число` считать **значимым**.
4. Оба значения числа и предыдущее больше `0`: изменение значимо, если
   относительное изменение к предыдущему значению составляет не менее 1%:

   ```
   abs(new - old) / old * 100 >= 1
   ```

   Изменение меньше 1% считается незначимым.

## 2. Скидка появилась

`sale_price` была `null`, стала числом — **всегда значимое изменение**.

## 3. Скидка исчезла

`sale_price` была числом, стала `null` — **всегда значимое изменение**.

## 4. Изменение `sale_price` при наличии скидки в обоих прогонах

Если `sale_price` была числом и осталась числом, изменение значимо при том же
пороге не менее 1% относительно предыдущего значения:

```
abs(new - old) / old * 100 >= 1
```

Изменение меньше 1% считается незначимым.

## 5. Изменение `has_credit`

Любое изменение значения значимо:

- `false -> true`;
- `true -> false`.

## 6. Появился новый URL

URL есть в текущем прогоне, но его не было в предыдущем — **значимое изменение**.

## 7. URL пропал

URL был в предыдущем прогоне, но отсутствует в текущем — **значимое изменение**.
